## Horizon and determinism

Eight Counters aware/unaware jobs run. The four currently inspectable pairs
are exactly matched so far: 22/59, 22/59, 12/59 and 13/59 completed-prefix
successes in each aware/unaware arm. Maximum completed plan lengths are 285,
255, 730 and 1,105 actions. No current ledger contains a 10,000-action plan.
All emitted diagnostics still report zero horizon cutoffs.

This is internally consistent. At external action `t`, each root search is
limited by `10000 - t`; a trajectory may accumulate thousands of external
actions while each individual search remains much shallower than that current
remainder. When the wrapper reaches 10,000 external actions it terminates the
trajectory rather than launching a new root search with horizon zero. The live
aware campaign has not yet supplied the stronger example “10,000 external
actions and zero search cutoffs.”

The determinism audit is complete:

- repeated runs on the same CPU family were identical at every external action;
- different CPU families changed policy and child-statistic checksums;
- neither audited instance changed its selected action, trajectory or outcome;
- a fresh same-node aware/unaware replay was identical and recorded zero
  cutoffs.

Therefore random process timing is unsupported, CPU numerical variation is
real but not yet action-changing, and the old three-instance Drone Horizon
difference remains an uncontrolled historical build/process comparison.
